枚举法

在解决问题时，有些题目看起来没有特别巧妙的公式，也没有明显的规律。

这时候，我们可以考虑一种最朴素的方法：

把所有可能的情况都试一遍。

这种方法就叫做 枚举法。

枚举法也常被称为“暴力枚举”或“暴力搜索”。

枚举法是算法竞赛中非常重要的基本思想，不仅可以用来打部分分。很多复杂算法的第一步，都是先写出枚举做法，再想办法进行优化。

 

枚举法的核心思想非常简单，将所有可能的答案/状态一一列举出来，一次判断哪些是满足条件的答案/状态。

直接枚举所有未知变量

顾名思义，这是最直接的枚举，相当于我们去尝试破解一个密码锁，那么我们就一个一个尝试密码，直到密码锁解开。时间复杂度取决于状态总数。代码也比较好书写，只需要注意枚举的范围必须要覆盖到所有可行答案。有多少个未知量，就写几重循环。

枚举优化

多未知变量问题

有时，我们会经常遇到多未知变量枚举问题，朴素做法就是多重循环枚举每一个未知变量，时间复杂度与未知变量数量相关，例如三个未知变量的枚举时间复杂度为 O(n3)。那么，当数据范围过大时，朴素做法无法通过所有数据。

容易发现，我们解决的问题大多形如 a∗x+b∗y+c∗z+...=n 的形式。那么其实我们可以少枚举一个未知变量，因为当其他未知变量确定时，最后一个未知变量的值，可以通过解方程的思想求解出来。我们只需要判断求解出来的值是否合法即可。这样的优化能够让时间复杂度降低一维。

例题：整数组合(hard)

思路：

本题朴素做法很容易想到，直接枚举 a、b、c 的数量 x、y、z。验证 a∗x+b∗y+c∗z 是否等于 n 即可。时间复杂度：O(n3)。本题 n 最大值为 5000 。朴素做法无法通过。

那么，我们就可以只枚举 x 和 y。那么 z=n−a∗x−b∗yc。我们只需要验证 z 是一个非负数即可，即 n−a∗x−b∗y 是 c 的倍数。

时间复杂度优化为 O(n2)。

打标记、预处理思想

我们经常会遇到寻找某个范围中满足某种性质的数。朴素做法就是枚举所有数，依次判断每个数是否满足性质。但是，我们可以使用数组或其他数据结构提前预处理，将所有满足性质的数打上标记，那么后续判断时，只需要判断是否有标记，时间复杂度得到优化。

枚举排列

排列是数学里“按顺序安排对象”的概念。

比如有三个字母 A、B、C，把它们排成一列：

  • A B C

  • A C B

  • B A C

  • B C A

  • C A B

  • C B A

这些都是不同的排列，因为顺序不同就算不同。

一般来说，如果有 n 个不同元素，把它们全部排起来，排列数是：

n×(n−1)×(n−2)×⋯×2×1=n!。

枚举所有排列可以使用 DFS(深度优先搜索)，代码稍微长一些。C++ 中也有封装好的 STL直接使用，更加方便。

二进制枚举

二进制枚举通常用来枚举子集。当每个元素有两种选择时，采用二进制枚举，能很简洁的处理所有情况。

举个例子，现在有 3 枚硬币。那么每个硬币都有正、反两种情况。共 23=8 种情况。

我们可以考虑状态压缩。即使用一个 2 进制数来表示状态。

例如 4 个硬币的状态分别是正、正、反、反。那么对应的二进制数可以是 1100。

那么 4 个硬币的所有情况，就是从二进制数 0000 枚举到 1111。共 24=16 种情况。n 个硬币同理。

但是，直接枚举二进制数同样不是很方便。我们发现，这些数的十进制形式都是连在一起的。

n 个硬币的状态，就是从 0 枚举到 2n−1。所以我们可以考虑，枚举这个范围的十进制数，然后转为二进制，从而得到每一种具体的状态。
