第2章 C/C++ 集成开发环境与程序开发流程

要运行 C++ 程序，我们需要一个 IDE（集成开发环境）。本章介绍常用 IDE、Dev-C++ 的使用、一个程序从写下到运行的完整流程，以及代码注释的写法。

2.1 什么是 IDE

IDE（Integrated Development Environment，集成开发环境）把 编辑器、编译器、调试器 和图形界面集成在一起，让你在一个软件里就能完成"写代码 → 编译 → 运行 → 找错"的全部工作。

常用 C/C++ IDE：

IDE特点
Dev-C++轻量、免费，内置 GCC 编译器，NOI/NOIP、GESP 等竞赛常用
Code::Blocks开源免费、跨平台、可插件扩展
Visual Studio功能强大，适合大型项目，体积较大
CLionJetBrains 出品，智能提示强（学生/非商业免费）
Visual Studio Code编辑器 + 插件，轻量灵活
tip

GESP 考试与信奥竞赛普遍使用 Dev-C++（或小熊猫、VSCode 等），本手册示例均以 Dev-C++ 风格编写，语法完全通用。

2.2 程序的完整生命周期

一个 C++ 程序从诞生到运行，要经历四个阶段，遇到错误就回头修改：

  1. 编辑：在编辑器里写源代码，保存为 .cpp 文件。
  2. 编译：编译器把 .cpp 翻译成机器能执行的程序；若有语法错误，编译失败，回到编辑修改。
  3. 运行：执行编译生成的可执行文件，得到输出结果。
  4. 调试：若结果不对（逻辑错误），用断点、单步等手段排查。

2.3 Dev-C++ 的安装与基本使用

2.3.1 安装

  1. 下载 Dev-C++ 安装包（如 Dev-Cpp 5.11 或新版本）；
  2. 运行安装向导，同意许可协议；
  3. 选择安装路径（建议路径不要含中文和空格）；
  4. 选择组件，完成安装。

2.3.2 编写并运行第一个程序

  1. 启动 Dev-C++，首次可设置简体中文与字体；
  2. 新建源代码：文件 → 新建 → 源代码；
  3. 输入以下代码：
#include <iostream>
using namespace std;
int main()
{
    cout << "Hello World!" << endl;
    return 0;
}
  1. 编译：菜单 运行 → 编译，快捷键 F9。若底部出现错误，按提示修改；
  2. 运行：菜单 运行 → 运行，快捷键 F10，弹出控制台窗口显示结果。
caution

路径与文件名不要使用中文，否则部分旧版编译器可能报错。例如把文件命名为 test.cpp 而不是 测试.cpp。

2.4 调试程序（找 Bug）

调试用于发现逻辑错误（程序能编译能运行，但结果不对）。

2.4.1 核心操作

  1. 设置断点：点击代码行号左侧，出现红点；程序运行到该行会暂停。
  2. 进入调试：运行 → 调试，快捷键 F5。
  3. 单步执行：
    • F10（Step Over）：单步执行，遇到函数调用直接跑完，不进入函数内部；
    • F11（Step Into）：进入函数内部逐行执行；
    • Shift+F11（Step Out）：跳出当前函数。
  4. 监视变量：在 Watch 窗口添加变量名，或在代码上悬浮鼠标，查看变量当前值。
  5. F5 继续运行到下一个断点；Shift+F5 停止调试。

2.4.2 调试注意事项

  • 断点要有针对性，不要大面积乱设；
  • 重点观察变量值是否符合预期（例如循环变量有没有越界）；
  • 调试结束清除无用断点。

2.5 程序的注释

注释是写给"人"看的说明文字，编译器会完全忽略，不会执行。

2.5.1 注释的作用

  1. 解释代码逻辑，方便自己和他人阅读；
  2. 临时屏蔽一段代码，对比调试效果；
  3. 提升可维护性，方便日后修改。

2.5.2 两种注释

单行注释 //：从 // 开始到本行末尾都是注释。

// 输出一句问候语
cout << "Hello";
int a = 10;  // 定义变量 a 并赋值为 10

多行注释 /* ... */：/* 开始，*/ 结束，可跨多行。

/*
  这是多行注释
  可以写很多行说明
*/
int score = 95;
danger

多行注释不能嵌套多行注释！ 下面的写法会报错：

/*
外层注释
/* 这行想再写一段注释 —— 这里会出错 */
*/

正确做法：多行注释内部可以写单行注释 //，或用一行 // 代替。

2.5.3 使用建议

  1. 不要过度注释——一看就懂的代码不必写；
  2. 改了代码要同步更新注释，避免"注释说的是旧的、代码是新的"；
  3. /* 与 */ 必须成对，漏写一个会把大片代码误当成注释；
  4. C++ 同时支持 // 与 /* */；C99 之后的 C 语言也支持 //。
tip

良好的注释习惯是程序员的基本功。考试时虽然不考注释，但写清楚思路能帮你减少低级错误。

2.6 随堂检测

1. 下列工具中，属于集成开发环境（IDE）的是（ ）。

  • A. Windows
  • B. Dev-C++
  • C. GCC（仅编译器）
  • D. 记事本
查看答案

答案：B。Dev-C++ 集编辑、编译、调试于一体，是 IDE；GCC 只是编译器，记事本是纯文本编辑器。

2. 关于注释，下列说法正确的是（ ）。

  • A. 注释会被编译进最终程序，影响运行速度
  • B. 多行注释可以任意嵌套多行注释
  • C. // 是单行注释，从它到行尾都无效
  • D. 注释可以提高程序运行效率
查看答案

答案：C。注释被编译器忽略，不会执行也不影响效率；多行注释不可嵌套。
